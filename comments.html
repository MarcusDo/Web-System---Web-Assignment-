Overall Website Structure

My website consists of four HTML pages with distinct purposes and one shared CSS stylesheet. Its structure supports consistent presentation and clear navigation, with:

  • A consistent navigation bar links to all four pages, allowing direct navigation without returning to Home or using the browser’s back button.
  • The shared stylesheet provides a consistent visual theme across all pages.
  • Relative paths preserve link functionality after uploading to Ed, provided the folder structure remains unchanged.
  • Overview cards on Home provide descriptions and links to help users explore the website.

Internal HTML Structure

Shared structure

Each page separates document information from visible content. The <head> contains metadata, the page title and the stylesheet link, while the <body> contains a <header> with the logo and <nav>, a <main> for primary content, and a <footer> for author information.

Within <main>, I use <section> to group related content under headings and <div> for layout containers such as cards. Semantic elements clarify the content’s purpose for browsers and assistive technologies, keeping the structure understandable without CSS. A <div> has no specific semantic meaning.

A consistent header, navigation and footer make the pages familiar to visitors, although shared navigation changes require updating every HTML file.

Differences between pages

The main differences between my pages are within <main>, where I choose elements to suit each page’s content:

  • Home: Paragraphs and a portrait introduce me, followed by four cards with page descriptions and navigation links.
  • Past: Three tables organise my studies, experiences and technical skills for comparison. The rowspan attribute groups subjects within the same study area.
  • Future: Two cards separate my goals from skills to improve, each using a heading and an unordered list.
  • Comments: Headed sections, paragraphs, tables, cards, lists and diagrams explain the website’s structure and design.

Classes, IDs and navigation

Here, I use classes for reusable styling and IDs to identify unique sections for navigation within a page. An element can use both: its class applies shared styling, while its ID provides a unique link destination.

I provide four navigation links on every page, plus internal links on Past and Comments to reach specific sections. I use relative paths so links continue working after upload, provided the folder structure is preserved.

Text Emphasis and Accessible Content

I use <span> with a class to visually highlight my name through CSS while keeping it inline, whereas <strong> conveys semantic importance. I also use table captions to identify each table’s purpose and scoped column headings to associate labels with their data. My portrait includes alternative text describing the image when it cannot be seen. Even without CSS, headings, paragraphs, lists and tables preserve the content’s logical structure.

Aesthetics and Design Reasoning

My website design uses a simple grey, white, black and blue colour scheme to create a professional look and keep the focus on the content.

Design choices and their intended effects
Design choice Reasoning and intended effect
Light grey background and white header with black border I choose a neutral light grey background to keep attention on the content. The white header and black border distinguish navigation from the content while scrolling.
Dark text and blue accents I use dark text to provide strong contrast against light backgrounds for readability. Blue accents highlight links and my name, while blue borders connect elements to the website’s colour theme.
Arial and fallback fonts I choose Arial for its familiar, readable appearance across paragraphs, lists and tables. Helvetica and a generic sans-serif provide alternatives if Arial is unavailable.

Tables I choose tables to align related information about my experiences, skills, CSS techniques and design decisions, making comparisons easier than reading separate paragraphs. Blue headers with white text distinguish column labels from the entries.
Image styling I give my portrait a blue border to match the colour theme and rounded corners to echo the cards’ softer appearance. I centre graph diagrams and adjust their widths so their details are readable and integrated with the surrounding content.
Consistent navigation and footer I keep navigation and footer placement consistent so users encounter a familiar layout on every page. Highlighting the active link identifies their current page, while centred, italic footer text and a separating border distinguish author information from the main content.
Section spacing and borders I use spacing and thin top borders to separate major topics, giving readers a clear visual break and making sections easier to identify and scan.

Accessibility and Resizing

The two tables below illustrate in details my implementation/ design and test for accessibility, and recovery under scenario when img/css being disable as well as adaptability, resizing across different browser and monitor size, zoom

Accessibility features and their purposes
Area Implementation and reasoning
Image alternatives I use alt attributes to describe my portrait and diagrams when they cannot be seen. Nearby explanations also communicate the diagrams’ key information, so essential content does not depend entirely on images.
Usability without CSS or images I organise headings, paragraphs, lists, tables and links in a logical HTML order. When I disabled CSS, the content remained understandable. With images disabled, the written explanations and navigation remained available.
Keyboard navigation I use native HTML links to support keyboard access. I checked Tab and Shift+Tab navigation and Enter activation, confirming that links were reachable in a logical order with visible focus indicators.
Navigation clarity I provide consistent menus and descriptive link text to make destinations clear. Blue text and an underline identify the current page visually, while aria-current="page" communicates it to assistive technologies.
Text readability I use Arial with fallback fonts, distinct heading sizes and a line height of 1.6 to support reading and scanning. Paragraph and section spacing separate ideas and reduce crowding.
Colour contrast I use dark text against light backgrounds for readability. Calculated contrast ratios are approximately 13.48:1 for body text, 6.69:1 for general links and 5.90:1 for white table-heading text against blue. These measurements assess the specified colour pairs, not overall accessibility.
Resizing and zoom I use proportional widths to adapt content to the available space. At 650px or below, cards form one column and header floats are removed. During my resizing and zoom tests, content remained readable and navigation remained usable.
Sticky header and internal links I apply scroll-margin-top to selected anchor destinations to leave space above them. I checked internal links to confirm that destination headings remained visible below the sticky header.
HTML structure I declare English as the document language and use descriptive page titles, meaningful headings and semantic page regions. These help assistive technologies and search engines interpret the content and its organisation.
Tables I provide captions to identify each table and scope="col" on column headings to associate labels with data. I also checked that table content remained readable when the browser window narrowed.
Print usability I checked print preview to confirm that content remained complete and readable without overlap or clipping. Headings, text and table organisation preserved meaning without relying on background colours.
JavaScript independence I use HTML for essential content and navigation, so users can read the website and follow its links without JavaScript.
